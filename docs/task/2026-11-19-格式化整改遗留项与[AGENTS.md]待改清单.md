## 二、AGENTS.md 待改点 (等大改造时一并处理，现在不要单独改)

### 2.1 「文本规范 (全角圆括号)」一节已部分过期

现状：该节给出的批量处理命令是

	jsinvokefiles modify process-text formatReplaceMarkdownFullWidthParenthesesOnly --script-seq 1 --file <显式文件路径...> --force

问题：

- 该命令属于工作区 `vscode-workspace-temp` 的工具链，本仓内没有这套工具
- 该命令会顺带移除行尾空白并生成 `*.js_inv.bak` 备份；而本仓 `.editorconfig` 明确
	`trim_trailing_whitespace = false`，两者口径冲突
- `*.js_inv.bak` 与本仓「`.bak` 永不纳入仓库、永不处理」的约定冲突

待定方向：保留「圆括号一律半角」这条规则本身，替换或删除与之绑定的旧命令与备份说明。

### 2.2 「调试留痕」一节与 `.bak` 约定冲突

现状：该节把 `src/index.ts.bak` ~ `.bak7`、`package.json.bak`、`tsconfig.json.bak`
描述为「排查回归问题时可按时间顺序对比」的备份。

问题：用户已明确定调 —— `.bak` 代表某一时刻的文件快照，**永远不纳入 Git 仓库，
也永远不做格式与规范化处理**。目前这些文件仍被 git 跟踪，属于历史遗留。

待定方向：说明 `.bak` 的处置口径 (移出仓库 / 保留在工作区但取消跟踪)，并同步该节措辞。

### 2.3 「构建」一节的产物换行未提及

现状：该节说明 `tsc` 产物直接落在仓根。但 tsc 输出的 `index.js` / `index.d.ts`
在工作区是 **LF**，而 `.gitattributes` 声明 `*.js` / `*.d.ts` 为 `text eol=crlf`。
入库 blob 为 LF (`i/lf`)，检出后工作区为 CRLF，属正常行为，但**刚跑完 build 的瞬间**
工作区是 LF，与属性声明短暂不一致。

待定方向：说明「build 之后工作区产物为 LF 属正常，git 检出时才转为 CRLF」，
避免后来者把它误判为格式问题而去手改产物。
